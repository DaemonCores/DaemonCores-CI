## `scripts/gen_docs.py`

gen_docs.py — generate the technical reference from source comments.

Usage:
    python3 gen_docs.py [--root DIR] [--check]

``--root`` is the repository to document (default: the current directory). The
Python and shell files to document are the ones its ``Makefile`` lists in
``PYTHON_SRCS``, ``SHELL_SRCS`` and ``POSTINST_SRCS``.

Reads the Google-style docstrings of the Python sources and the header comment
block of every shell script, and rewrites the generated region of
``docs/reference/Reference-Python.md`` and
``docs/reference/Reference-Shell.md``.
With ``--check`` nothing is written and the exit status is 1 when a page is
out of date (used by CI).

### `_read_makefile_list()`

```text
Return the paths listed under the Makefile variable ``name``.

Args:
    root: Repository root holding the ``Makefile``.
    name: Makefile variable assigned with backslash continuation lines.

Returns:
    The listed paths, in declaration order.
```

## `scripts/check_docstrings.py`

check_docstrings.py - Google docstring presence gate for Python files.

Usage:
    python3 check_docstrings.py [--root DIR] [PATH ...]

ruff ignores private callables and pydoclint only checks docstrings that
exist, so neither catches a helper or a test with no docstring at all. This
gate closes the gap: every module, class and function (private and test ones
included) is documented, and a callable with arguments, a return value or a
raised exception explains them in a Google-style section instead of a lone
summary line.

``PATH`` is a file or a directory searched recursively (default: ``scripts``
and ``tests`` under ``--root``).

### `needs_sections()`

```text
Name the docstring sections a function must carry.

Args:
    node: Function definition to inspect.

Returns:
    The section headers (``Args:``, ``Returns:``, ``Raises:``,
    ``Yields:``) the docstring has to contain.
```

### `problems()`

```text
Collect the docstring defects of one Python file.

Args:
    path: Python file to inspect.

Returns:
    One human-readable line per missing docstring or section.
```

### `collect()`

```text
Args:
    root: Repository root.
```

## `scripts/check_docs.py`

check_docs.py - verify that the documentation still matches the tree.

Usage:
    python3 check_docs.py [--root DIR] [--docs DIR]

Kronn writes claims as ``[src: file: path:LINE]`` citations and Markdown
pages link to each other. Nothing else notices when a file moves or shrinks,
so the citations rot silently. This check fails on:

* a citation whose file does not exist;
* a citation whose line is past the end of the file or blank;
* a relative Markdown link whose target does not exist.

Pages under ``.kronn-citation-originals`` are Kronn backups and are skipped.

### `pages()`

```text
List the Markdown pages to verify.

Args:
    docs: Documentation directory.

Returns:
    Sorted Markdown files, Kronn backups excluded.
```

### `check_citation()`

```text
Args:
    root: Repository root.
    target: Cited path relative to ``root``.
    first: First cited line, or an empty string.
    last: Last cited line, or an empty string.

Returns:
    A defect description, or an empty string when the citation holds.
```

### `check_page()`

```text
Verify the citations and relative links of one page.

Args:

    page: Markdown page to scan.

Returns:
    One line per defect.
```

## `scripts/check_kconfig.py`

check_kconfig.py - Kconfig symbol gate for kernel config fragments.

Usage:
    python3 check_kconfig.py --tree DIR [--config FILE] FRAGMENT [FRAGMENT ...]

``make olddefconfig`` silently ignores a symbol the kernel does not know, so a
fragment that names a renamed or removed option builds a kernel without it and
nothing fails. This gate closes the gap against the kernel the build uses:

* every symbol of every fragment must be declared by a Kconfig file of the
  kernel source ``--tree``;
* with ``--config`` (the ``.config`` produced by ``make olddefconfig``), every
  symbol must also end up with the value the fragments ask for, which catches
  an option dropped because a dependency is not met.

The last fragment wins, as with ``merge_config.sh``.

### `parse_fragment()`

```text
Read the requested values of one fragment.

Args:
    path: Config fragment (``CONFIG_X=y`` or ``# CONFIG_X is not set``).

Returns:
    The requested value by symbol, ``n`` for a symbol that must be unset.
```

### `declared_symbols()`

```text
Collect every symbol declared by a Kconfig file of a kernel tree.

Args:
    tree: Root of the kernel source.

Returns:
    The symbols as ``CONFIG_<name>``.
```

### `config_values()`

```text
Read the final values of a generated ``.config``.

Args:
    path: The ``.config`` written by ``make olddefconfig``.

Returns:
    The value by symbol, ``n`` for a symbol that is not set.
```

### `check()`

```text
Compare the requested options with the kernel.

Args:
    wanted: Requested value by symbol, all fragments merged.
    declared: Symbols the kernel Kconfig files declare.
    final: Values of the generated ``.config``, or ``None`` to skip that
        comparison.

Returns:
    One line per defect; empty when every option is honoured.
```

### `main()`

```text
Run the gate.

Args:
    argv: Command-line arguments, ``sys.argv[1:]`` when ``None``.

Returns:
    ``0`` when every option is honoured, ``1`` otherwise.
```

## `scripts/patch_guard.py`

patch_guard.py - sha256 guard of the kernel files the patches touch.

Usage:
    python3 patch_guard.py --tree DIR --lock FILE [--update] PATCH [PATCH ...]

A patch written against one kernel can silently mis-apply on the next one even
when ``patch`` accepts it. The lock file records, for every pre-existing file
the patches modify, the sha256 it had in the kernel the patches were last
validated against. The guard hashes those files in the pristine ``--tree``,
before any patch is applied, and refuses the build when one differs from the
lock or has no reference. With ``--update`` it rewrites the lock from the tree
instead, merging into the existing lock so several runs (one per class and
architecture) build the full reference; a CI job runs it to propose the new
references.

### `touched_files()`

```text
List the pre-existing files a patch modifies.

Files the patch creates (source ``/dev/null``) have no reference state and
are left out.

Args:
    patch: Unified diff text.

Returns:
    The paths relative to the kernel root, without the ``b/`` prefix.
```

### `file_hashes()`

```text
Hash files of a kernel tree.

Args:
    tree: Root of the pristine kernel source.
    files: Paths relative to ``tree``.

Returns:
    The sha256 by path; a file missing from the tree maps to ``missing``.
```

### `check()`

```text
Compare the tree hashes with the lock.

Args:
    current: sha256 of the touched files in the tree.
    lock: Reference sha256 by path.

Returns:
    One line per defect; empty when every file matches its reference.
```

### `main()`

```text
Run the guard.

Args:
    argv: Command-line arguments, ``sys.argv[1:]`` when ``None``.

Returns:
    ``0`` when every file matches (or after ``--update``), ``1`` otherwise.
```
